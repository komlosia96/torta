# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static, single-page birthday gift in Hungarian: a photoreal three.js scene (cake with number candles, table, blurred room, plush unicorn, leather photo album). `BUILD_SPEC.md` (v2) is the source of truth for behaviour and design; `README.md` is the author-facing guide (editing content, photos, deploy). Read the spec before changing behaviour.

## Hard rules (from BUILD_SPEC.md section 0)

- No build step, no package.json. Plain ES modules loaded by `index.html`. The only library is three.js r160, vendored at `js/vendor/three.module.min.js`; never add another dependency or a CDN import.
- No third-party requests at runtime. Every texture is generated on a canvas in `js/tex.js`; fonts are self-hosted in `assets/fonts/`.
- No em-dashes or en-dashes anywhere (code, comments, UI copy, docs, including this file). Use commas, periods or hyphens.
- Never invent the slice message. There is one, the author's own text in `js/content.js` ("Szeretlek és hiányzol :((", with Hungarian accents); do not reword it.
- Never broken without assets: a missing photo must fall back to a pastel numbered placeholder, and the blow flow must always have a tap fallback.
- Primary target: iPhone 17 Pro in Safari, portrait (test at 402x874 and 402x760). Other phones 360 to 430 px wide and desktop must still frame well. Phones are portrait only (author rule): iOS cannot lock rotation, so `#turnBack` (index.html, `.turn-back` in style.css, text `ui.turnBack`) covers the page at z-index 20 when a touch screen is landscape and at most 500 px tall; nothing underneath is reset. Test it at 740x360 in the preview (widths under 768 emulate touch; 874x402 does not).

## Architecture

**Boot and state (`js/main.js`).** Uses top-level `await createWorld(...)`; if it returns `null` (no WebGL) a message is shown and boot stops. Owns the state machine `WISH -> BLOWING -> CELEBRATE -> PLAY`, all 2D DOM UI (the unicorn's speech bubble, buttons, toast, hearts), and the lock rule (slices only open in `PLAY`). The wish UI (author rules): before the tap there is only the button (`ui.blowButton`, "Kattints ide!") with no hint under it; the tap asks for the microphone and shows `ui.blowHint` (two lines, split by `
`, `.hint` has `white-space:pre-line`), which already says to tap the candles if blowing does not work, so it stays in every fallback case (denied, timeout, in-app browser) and there is no separate fallback line (`#hint2` stays hidden). Inside main.js the world object is also referred to as `cake`; it is the same object. `celebrate()` is idempotent and `reset()` must undo everything it does. The speech bubble (`#say` plus the SVG tail `#sayTail`) is placed by `placeSay()` from `world.unicornHead()` and `world.candlesRect()`; it says `content.intro.text` before the wish and `content.happy.text` ("Boldog szülinapot, Kicsim!", capital K by author's choice) after. Author rule: the tail leaves the bubble on the right and ends beside his mouth, so it never crosses the cake. A round reset button (`#resetBtn`, top-left) calls `reset()` for her too, not only in dev mode.

**3D scene (`js/world.js`).** Owns the renderer, lights, the table, the cake stand, the 3D album model, picking and the slice pull-out animation. Key mechanisms that span files:
- *Framing:* `fit()` solves the camera distance so the key points fit: `cakePts` (stand rim and foot, flame tips) and `sidePts` (album box corners, plush extents including its mirrored tail) set the vertical band (lowest point at about 80% down, nothing above the top UI) and must fit the width, because the album and the plush must be fully visible on the iPhone (author rule). `setViewOffset` (lens shift, no perspective change) then centres the group across and places the foot. Anything new that must stay on screen should be added to these point lists.
- *DOM overlays tracked to 3D:* the plush unicorn, the album button and the candle tap buttons are DOM elements in `#ov`, positioned in `placeOverlays()` by projecting world points. `fit()` calls it on resize; anything that moves a tracked object must re-place its overlay.
- *Render on demand:* nothing renders unless `invalidate()` is called. The rAF loop keeps running only while `anims` is non-empty or candles are lit/smoking (`C.anyLit`, `C.busy`). Use `animate(ms, step, done)` for any motion: it also lands the final state via `setTimeout` if frames are throttled, so state never sticks. Shadow map `autoUpdate` is off and `render()` flags it each frame, except while a slice is out and no note is moving (`shadowsKept`): nothing in the room moves then, and redrawing its shadows was much of each frame while the message is written. If the WebGL context is lost (phones under memory pressure, a backgrounded tab), everything 3D vanishes and only the DOM unicorn stays; the `webglcontextrestored` handler rebuilds the PMREM reflection map and calls `invalidate()`, so test with `WEBGL_lose_context` (`loseContext()` then `restoreContext()`) after touching it.
- *Reading a slice:* the open slice is moved to camera layer 1 and drawn after a full-screen scrim pass (`scrimScene`) with a depth clear, so the rest of the scene darkens behind it inside WebGL. The plush (a DOM layer above the canvas) never disappears meanwhile (author rule): `veilPlush()`, called from `render()`, dims him by the scrim's own amount (`filter: brightness`) and cuts the screen outline of whatever is on layer 1 (the slice, from its real extent `sliceExt` minus the bites taken, so no gap shows; the held or flying note) out of him with an even-odd `clip-path`, so it stays in front of him. The icing text mesh is created lazily per slice (`textMesh`) and piped letter by letter through the sentence by one round tip moving at a steady speed along the middle of each stroke (author: it must look like it is being drawn there; a straight wipe, and then a flood through each letter's ink that split at forks and filled loops from both sides, both read as filling in). `TX.icingText` draws the text letter by letter (each glyph at its place in the line, layer by layer: shadows, outlines, cream, highlight) and returns a reveal map (`revealMap` / `revealWork` / `letterTimes` in tex.js). Per letter, in a small box of its own: its own shape (on a `willReadFrequently` canvas, measured with the same `middle` baseline it is drawn with) is its ink, with its shadow and highlight; it is thinned to one-pixel middle lines (Zhang-Suen `thin`, short corner twigs pruned) and walked like a pen, set down at the top-left-most free end, straight on at forks, lifting to the next top-left-most undrawn end (crossbars, accents, the second dot of a colon); every pixel gets the soonest time the round tip covers it (time at a line point plus the distance, a bucket queue, reach half the stroke plus the shadow), ink beyond that just after its neighbour. Then the letters are laid end to end (author rule: no part of a letter before the one before it is finished, soft edges included): each starts 4 px of pen travel after the last visible pixel of the one before (a space or a new line waits longer); overlapping ink stays with the earlier letter. Do not go back to cutting the line into columns: handwritten letters reach into their neighbours (the S's tail under the z, the y's tail under the n, accents), and those bits were drawn with the wrong letter. Time is stored in red and green; the shader reads the map with a `highp` sampler (by default a texture is read at low precision, half floats on a phone, too coarse for it: the front jumped and letters ran together on the iPhone while the PC looked fine) and with `NearestFilter` and no mipmaps, so neighbouring letters' times never blend. The work is a generator run a few ms at a time between frames from a moment after load (`revealStep(tex, ms)`; `textMesh().userData.ready()` finishes it at once if the slice opens first and sets `uSoft`, a two-pixel soft front, and the letter count); the pace is 170 ms a letter, 2 to 5 s in all; the text material's shader fades it in against `uReveal`; `biteMaterial` keeps a material's own `onBeforeCompile`), only the first time (`userData.read`): once read it stays written on the slice in the cake (no gold heart, author rule) until `resetVisited()`. The slice view has no close button (author rule): a tap anywhere but the slice, or Escape, closes it. Its bite hint shows only once the message is written (`openSlice(k, written)` adds `.hint-on`). The outline is walked finely along the cut sides, the rim and each bite's edge, with the exact corners where a bite meets a side found by halving (`walk`), then widened 1.5 px: sampled every half centimetre, those corners were cut off and he showed over up to 8 px of a bite's sponge wall. The cut also covers where the slice was a frame earlier (`veilPrev`), so a phone that shows the new 3D frame and the new cut a frame apart never lets him in front of a moving slice; one more frame trims it once it rests. While veiled the plush host gets `.veiled`, which switches off every animation and transition in him and any layer of his own (never add `translateZ` or `will-change` there): Safari leaves separately composited layers out of the cut-out, so first his dance and then a forced layer let him show through the slice; he holds still until the slice is back. The hole runs opposite to the frame round it, so it needs no `evenodd` keyword.
- *Eating the slice* (author request): once its whole message has been written on it (author rule: until then a tap on the slice does nothing at all, `biteSlice` returns `{ wait: true }` and main.js ignores it, while a tap beside it still closes it; a slice opened again, already written, can be bitten even while it is still arriving), every tap on the slice takes one of 5 bites from the pointy end to the rim (`BITES`, laid out so each bite reaches past both sides of the slice where it overlaps the last and the fourth stops short of the rim: what is left is always one piece, author rule); main.js asks `world.biteSlice(x, y)`, a layer-1 raycast (null means it missed, so the tap closes as before) that counts only hits on what is left of the slice (`solidHit`, author rule: a tap where the slice used to be is not a tap on it): the raycast sees whole meshes, so a hit inside a bite taken, on a bite wall outside the slice or inside another bite (each wall is a whole ring, mostly hidden), on a hidden mesh, or on the message's plane is skipped, the same rules as the drawing. Bites are ragged vertical cylinders worked out in cake coordinates (the materials, a wall's, the note, and also the slice's own materials, the icing's material and both its textures, and the dark veil `scrimScene`, all used for the first time when the slice opens, are made ahead with their shaders built, `prepEat` / `buildShaders`, once as lit on layer 0 and once on layer 1, because the layer-1 pass leaves the candles' point lights out and a shader is built for its lights: made at the first bite they held that frame up and the bite showed late, author: laggy; `uneat` keeps them; `uToCake`, synced in `render()` by `syncBites()` from this frame's slice pose, `updateWorldMatrix(true, false)`: last frame's made the bites trail a moving slice so it warped, author: glitchy): the slice's meshes get cloned materials (`biteMaterial`, `onBeforeCompile`) that discard what is inside any bite, and each bite gets a wall mesh (`biteWall`, the same ragged cylinder in the sponge material, facing into the bite, its u the distance from the cake's centre as on the cut faces so it is sponge all the way through, kept only inside the slice and outside the other bites) so the cake reads solid, never hollow (author rule). A strawberry a bite reaches is eaten whole (`userData.eaten`, kept hidden by `setBerries`). Closing a slice while it is still arriving or being written stops both at once (`openSeq`), so the open and close animations never fight. If the screen changes size while a slice is read, `fit()` calls `refitOpen()`, which puts the slice (and a held note) where the new view wants it. The last bite shrinks away what is left; the slice is then `eaten`, hidden in the cake (its empty place ignores taps, author rule; picking skips eaten slices), the bottom hint changes to `ui.eatenHint`, and once put away a paper note (`showNote`, `TX.noteTex(content.plateNote)`; built, texture-uploaded and compiled ahead at the first bite by `makeNote`, because building it in its first frame stalled the drop; at the last bite the 3D note itself comes up where the slice was (`presentNote`, layer 1, facing the camera at the big note view's size, so the DOM paper stays hidden by `.note3d`), and closing carries that same note down onto its spot (`placeNoteDown`), author rule: it must look like it is being put down; only this first time, later views of the note use the DOM paper and its fade; the speech bubble stays hidden by `body.say-hold` until it has landed, author rule) lies on the table where `o.noteSpot()` (main.js) points: the middle of the screen, halfway between the album's bottom and the text below (author rule), found on the table plane by a camera ray in `placeNote()`, which `fit()` repeats on resize; tapping it (`onNoteTap`) shows the note big again, as a picture the 3D view draws of the note held up exactly as it first was, level, in the same light and at the same size and place (`world.noteImage()` = `noteShot()`, drawn on layer 1 over nothing and read back from the WebGL canvas in the same task; `.plate-paper`, with no filter of its own, CSS tilts it 2 degrees as the 3D note was) so it is the same note every time (author rule) (main.js `showNote()`; `.plate-only` shows the slice layer's own `.scrim`, the album view's blur and dim, and nothing is hidden, not even the speech bubble or the text, author rule; on close the note fades first and the page stays dimmed until it is gone). No plate, and no close button in the note view: any tap closes it (author rules). `resetVisited()` calls `uneat()`, which restores everything.

## Verification quirks

- When the preview pane is hidden, rAF and CSS/Web animations pause, so early screenshots can look half-finished. world.js animations still finish on their timers; take a fresh screenshot or reload before judging.
- `lowEnd` (4 or fewer cores, or a slow frame check after load) lowers pixel ratio, shadow map size, blur and confetti. Check both paths when touching performance-sensitive code.
- Motion is too quick to screenshot. To step through it, slow time in the page: replace `performance.now` with a scaled clock, wrap `requestAnimationFrame` to pass that clock, and stretch `setTimeout` by the same factor (world.js `animate()` reads all three); then take zooms a second or two apart.
- A first-time stall is usually a shader being built: count `linkProgram` calls (wrap it on `WebGL2RenderingContext.prototype`) around the action, and diff the `shaderSource` texts against those built ahead; three.js writes light counts into the source, not as defines, so a different set of lights means a new shader.
- To check that Ákos never shows over the slice, a temporary check inside `veilPlush()` that projects every vertex of the open slice (skipping bitten parts, the bite walls outside the slice and the text plane's clear corners) and tests it against the cut-out hull worked well; it found the 8 px bite-corner misses. Remove it afterwards.
- Old console errors stay in the preview's log across reloads (an "Uncaught SyntaxError" from an earlier load kept showing): log a marker before reloading and only trust errors after it.
- Check the spec's testing checklist (BUILD_SPEC.md section 12), especially framing at 360x640, 390x844, 430x932, landscape and desktop.
